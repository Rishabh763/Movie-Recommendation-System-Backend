# Movie Recommendation System: Backend

Training pipeline and Flask API for the
[movie recommender web app](https://github.com/Rishabh763/Movie-Recommendation-System).
Models are trained offline on **MovieLens 32M** (32M ratings, 200k users) and served from a
4 MB set of learned embeddings; a website user's ratings are folded into the model in closed
form on each request, so the API never retrains and answers in a few milliseconds.

## Results

Per-user **temporal** split: each user's most recent 20% of ratings are held out, so every
model predicts a user's future from their past. 25.5M train / 6.3M test ratings, 200,945
users, 23,350 movies (movies with ≥ 20 ratings). Ranking metrics over 20,000 sampled test
users, ranking all movies they haven't rated; a held-out rating ≥ 4 counts as relevant.

| Model | RMSE ↓ | Recall@10 ↑ | NDCG@10 ↑ | Catalog coverage@10 |
|---|---|---|---|---|
| Popularity (most rated) | – | 0.0744 | 0.0713 | 0.9% |
| Popularity (damped mean rating) | – | 0.0260 | 0.0210 | 0.2% |
| Bias baseline μ + b_u + b_i | 0.8666 | 0.0000 | 0.0000 | 0.1% |
| Item-kNN (mean-centered cosine, shrinkage) | – | 0.1195 | 0.1171 | 7.8% |
| Biased MF (ALS, k = 64) | **0.7883** | 0.0067 | 0.0051 | 22.8% |
| **Implicit ALS (k = 128)**, served | – | **0.1262** | **0.1174** | 8.0% |

Generated by `python -m ml.evaluate` (raw numbers in [`reports/results.json`](reports/results.json));
hyperparameters were tuned on a separate validation split, see [`reports/tuning.md`](reports/tuning.md).

What the table shows:

- **Implicit ALS improves Recall@10 by 70% and NDCG@10 by 65% over the popularity
  baseline.** Item-kNN is a close second (tied on NDCG, 5% lower recall).
- **Best RMSE ≠ best ranking.** Biased MF predicts ratings 9% more accurately than the
  bias baseline, yet is nearly useless for top-10 lists: maximizing predicted *rating*
  surfaces obscure movies with a few enthusiastic raters that users rarely watch.
  Implicit ALS also learns from *which* movies people chose to rate. This matches
  Cremonesi et al., *Performance of Recommender Algorithms on Top-N Recommendation Tasks*
  (RecSys 2010).
- **Rating-weighted confidence beats binary** by ~15% NDCG on validation: how much someone
  liked past movies helps predict what they'll watch next.
- Damped-mean popularity ("highest rated") ranks worse than raw popularity, for the same
  reason: what people rate highly and what they actually watch next differ.

The served system uses **implicit ALS for ranking** and **biased MF for the predicted star
rating** shown on each card.

## How it works

### Biased matrix factorization (explicit ratings)

$$\hat r_{ui} = \mu + b_u + b_i + p_u^\top q_i$$

trained only on observed ratings Ω (missing ratings are *unknown*, not zero):

$$\min \sum_{(u,i)\in\Omega} (r_{ui} - \hat r_{ui})^2 + \lambda n_u\lVert p_u\rVert^2 + \lambda_b n_u b_u^2 + (\text{same for items})$$

With items fixed, each user's problem is ridge regression with design
$X = [Q_{I_u}, \mathbf 1]$ and target $y = r_{u,I_u} - \mu - b_{I_u}$:

$$[p_u, b_u] = (X^\top X + n_u\,\mathrm{diag}(\lambda,\dots,\lambda,\lambda_b))^{-1} X^\top y$$

ALS alternates this closed form between users and items (`ml/models.py`, parallelized
with Numba). Scaling the penalty by $n_u$ is ALS-WR (Zhou et al., 2008).

### Implicit ALS (ranking)

Every rating is a positive interaction $p_{ui}=1$ with confidence
$c_{ui} = \alpha\cdot\max(r_{ui}-2,\,0.5)$; all unrated pairs have $p_{ui}=0$, $c_{ui}=1$
(Hu, Koren & Volinsky, 2008). Minimizing
$\sum_{u,i} c_{ui}(p_{ui} - x_u^\top y_i)^2 + \lambda(\lVert x_u\rVert^2 + \lVert y_i\rVert^2)$
over **all** pairs gives, for a user,

$$x_u = \Big(Y^\top Y + \lambda I + \sum_{i \in I_u} (c_{ui}-1)\, y_i y_i^\top\Big)^{-1} \sum_{i\in I_u} c_{ui}\, y_i$$

$Y^\top Y$ is shared by every user, so it is precomputed once.

### Serving by fold-in

The API keeps $Y$ (10,000 × 128), $Y^\top Y$, and the MF item factors. For a website
user with ratings $I_u$, it computes $x_u$ with the formula above (one 128 × 128 solve)
and scores the catalog with $Yx_u$. That is exactly one ALS user step, so new users are
handled without retraining. Tests check the fold-in against brute-force least squares and
against the `implicit` library's own `recalculate_user`.

- **Cold start:** no ratings → most popular movies. 1–3 ratings → blend of the ALS score,
  a genre profile ($\sum (r-3)\cdot g_i$) and popularity, z-scored.
- **Explanations:** for each recommendation, the user's liked movie (≥ 3.5★) with the
  highest cosine similarity in the item embedding becomes "Because you liked …".
- **Similar movies:** nearest neighbours by cosine similarity of $y_i$.

Measured locally: artifacts load in 0.3 s, a recommendation takes 3–5 ms, and the process
peaks at ~185 MB RSS (Render free tier: 512 MB).

## API

| Endpoint | Auth | Description |
|---|---|---|
| `GET /` | – | Health + model info |
| `GET /movies?q=&genre=&sort=popular\|rating\|year\|title&page=&pageSize=` | – | Search / browse the catalog |
| `GET /movies?ids=1,2,3` | – | Movies by id (bookmarks) |
| `GET /movies/<id>` | – | Details + TMDB overview + 12 similar movies |
| `GET /genres` | – | Genre list |
| `GET /poster/<tmdbId>?size=w342` | – | 302 to the TMDB poster image (cached a week) |
| `GET /recommendations?top=20` | Firebase ID token | Personalised picks with `predictedRating`, `because`, `strategy` |

The user comes from the verified token, never from a parameter; their ratings are read
from Firestore `users/{uid}.mlRatings`. TMDB lookups are cached in memory and in
Firestore (`tmdb_cache`), so each movie is fetched from TMDB at most once.

## Repository layout

```
app.py              Flask routes, auth, CORS
recommender.py      Loads artifacts; search, fold-in, recommend, similar (numpy only)
tmdb.py             Poster / overview lookup with memory + Firestore cache
ml/
  prepare.py        MovieLens CSV -> Parquet, filtering, per-user temporal split
  models.py         Popularity, bias baseline, item-kNN, biased MF (ALS), implicit ALS
  evaluate.py       Train + evaluate all models, tuning on a validation split
  export.py         Retrain on all ratings, write artifacts/
artifacts/          Served model (4 MB): item factors, Gram matrix, movie metadata
reports/            results.md / results.json / tuning.md
tests/              API, recommender and fold-in tests (pytest)
```

## Reproduce

```bash
pip install -r requirements-dev.txt
# Download ml-32m.zip from https://grouplens.org/datasets/movielens/32m/ and unzip it
python -m ml.prepare --raw path/to/ml-32m      # ~20 s
python -m ml.evaluate --tune                   # grid search + full evaluation
python -m ml.evaluate --ials-alpha 1 --mf-reg 0.05
python -m ml.export --ials-alpha 1 --mf-reg 0.05
pytest -q
```

The raw dataset is not in the repo: the MovieLens licence doesn't allow redistribution.

## Run the API locally

```bash
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
# .env: FIREBASE_KEY_PATH=serviceAccountKey.json, TMDB_READ_TOKEN=<TMDB read access token>
python app.py
```

| Variable | Purpose |
|---|---|
| `FIREBASE_KEY_B64` / `FIREBASE_KEY_PATH` | Service account (base64 in production, file path locally) |
| `TMDB_READ_TOKEN` | TMDB API Read Access Token, for posters and overviews |
| `ALLOWED_ORIGINS` | Comma-separated CORS origins (defaults to the Vercel app and localhost:5173) |
